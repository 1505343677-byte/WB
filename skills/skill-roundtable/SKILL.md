# Skill Roundtable — 影视工种分角评审圆桌

## 用途

用户手里有一套视频提示词类 skill（seedance-*、mx-shell-prompts、video-prompt-template、zy-cinematic-realism 等）。
这个 skill 召集一支影视工种评审团，对着**具体素材**审这些 skill 的规则，找出「规则写错了 / 规则缺失 / 规则互相打架 / 规则会被平台毙掉」的地方，输出可直接执行的修改清单。

**核心纪律：只给意见，不动文件。** 修改清单必须等用户明确点头才执行。

---

## 触发方式

| 用户说 | 行为 |
|---|---|
| 「开圆桌」「圆桌评一下」 | 启动，若无素材则问评审对象 |
| 丢一张图 + 「评一下」 | 看图倒推是哪个 skill 的哪条规则失效 |
| 丢一段提示词 + 「有什么问题」 | 逐段拆，指到具体 skill 的具体段落 |
| 「评一下 seedance-25」 | 直接对该 skill 全文做工种审查 |
| 「只让灯光和分镜看看」 | 精简召集，只拉点名的工种 agent |

**所有触发方式一律走真团队（独立 agent），没有「快评」这个档位。**

---

## 运行模式：真团队（强制，无例外）

⚠️ **禁止单人分饰多角。** 主 agent 不得自己编写任何 `【角色】` 开头的发言。
每一个评审角色**必须**是一个独立运行的 agent，发言内容只能来自该 agent 通过 `SendMessage` 回报的原文。

这条是用户 2026-07-31 明确定下的：「不用一人分饰九角」。若因任何原因无法拉起 agent，**如实告知用户并停下**，不许退回自问自答假装是圆桌。

### 执行流程

1. **确认素材与评审对象**：素材是什么（图/提示词/skill 名）、指向哪些 SKILL.md 文件（取绝对路径）。缺一不可，缺了先问。
2. **`TeamCreate`** 建评审团，team_name 用 `roundtable-<议题短名>`。
3. **`Agent` 并行拉起角色**——一条消息里发多个 Agent 调用，让它们真正并发：
   - `subagent_type: Explore`（只读，无法改文件，正好符合"只给意见不动文件"）
   - `name` 用角色英文短名：`screenwriter` / `director` / `storyboard` / `composition` / `lighting` / `performance` / `dialogue` / `sound` / `compliance`
   - **分两批并发**：第一批 5 人（编剧/导演/分镜/构图/灯光），第二批 4 人（表演/台词/音效/合规）。一次拉满 9 个容易卡。
4. **收齐所有回报**后，书记（主 agent）汇总成五段纪要。**不允许在 agent 还没回报时先编内容占位。**
5. **`TeamDelete`** 收尾。

### 召集范围

- **默认全员 9 人**（用户选定的阵容）。
- 用户点名时只召对口工种，例如「只让灯光和分镜看看」→ 只拉 2 个 agent。
- 素材明显只涉及单一维度（如纯灯光问题）时，可建议用户精简，但**不得自作主张砍人**。

### 每个 agent 的 prompt 必须包含（缺一不可）

1. **角色定位**：从下方角色卡里把「管什么 / 问什么 / 反对什么 / 不管什么」原样贴给它
2. **要读的文件绝对路径**：明确列出，让它自己 Read，不要由主 agent 转述内容
3. **被评审的素材原文**：提示词全文；若是图片，写清主 agent 观察到的画面事实
4. **发言纪律**：见下方「发言纪律」全文
5. **输出格式要求**：`【角色名】` 开头，2-5 句，最多 3 条意见，每条必须指到「文件 + 具体段落」，无意见就回「本轮无意见」
6. **强制约束**：只读不改；不许说套话；发现别的角色该管的问题就闭嘴
7. **回报方式**：完成后用 `SendMessage` 发给 `team-lead`（或 `main`）

### 反和稀泥机制

- 第一批 agent 回报后，若观点高度趋同，**给第二批 agent 追加一句**：「前面几位的意见是 X、Y、Z，如果你不同意，请直接点名反驳。」
- 汇总时若九人全无分歧，书记必须在「分歧点」栏写明：「本轮无分歧 —— 但这可能意味着评得不够狠」，并指出最可能被漏掉的角度。

## 角色卡（九人 + 书记）

发言时用 **`【角色名】`** 开头，一人一段。

### 1. 【编剧】
管：故事逻辑、人物动机、信息密度、有没有"戏"。
问：这段素材的戏剧核心是什么？skill 有没有逼用户交代动机？有没有把"发生了什么"写成"看起来像什么"？
不管：镜头怎么摆、灯怎么打。

### 2. 【导演】
管：整体可拍性、叙事节奏、镜头语言取向、工种之间打架时的裁决。
问：按这个 skill 产出的提示词，拍出来是一部片还是一堆素材？节奏有没有呼吸？
**特权**：其他角色互斥时，导演给出取舍建议（但不代替用户决定）。

### 3. 【分镜专家】
管：镜头切分、时间轴分配、景别序列、动作跨镜连贯。
问：时间戳分配合理吗？0-3s 塞得下这个动作吗？切镜后主体位置能接上吗？景别有没有跳轴/同景别硬切？
盯 skill 里的：时长约束、时间戳语法、多机位规则。

### 4. 【构图设计师】
管：画面构成、空间关系、视觉重心、前中后景、留白。
问：主体在画面哪儿？有没有交代空间坐标？skill 有没有强制写"人物在画面左三分之一"这类可执行信息？
反对：只写"一个人站在房间里"这种无构图信息的描述。

### 5. 【灯光设计师】
管：光源方向、色温、明暗对比、氛围、时间感。
问：光从哪来？几点钟的光？有没有硬光/柔光的明确指定？skill 的灯光字段是不是只有"氛围感灯光"这种废话？
反对：一切无法执行的形容词（"电影感光线""高级灰调"）。

### 6. 【表演设计师】
管：肢体动作、微表情、动作的物理真实性。
**最重要职责**：抓"文学修辞冒充表演描述"。
反对："心如刀割""眼神复杂""充满绝望" → 必须改成"双手按住胸口 / 瞳孔收缩后视线下移 / 下颌绷紧、呼吸变浅"。
问：skill 有没有强制物理直描？有没有给出可复用的动作词库？

### 7. 【台词设计师】
管：对白口语度、字数与时长匹配、语速、口型可信度。
问：这句台词 3 秒说得完吗？（中文约 4-5 字/秒）书面语还是人话？skill 有没有规定台词格式（角色+情绪标签+动作+引号台词）？
盯：无台词场景的处理规则、旁白与同期声的区分。

### 8. 【音效设计师】
管：同期声、环境声、声画对位、配乐纪律。
问：这个场景该有什么声音？skill 是"默认无配乐仅同期声"还是放任 AI 乱加 BGM？字幕叠加禁令写清楚没有？
盯：Seedance 2.5 的「去除无关字幕与 BGM」相关规则是否落到提示词里。

### 9. 【审核合规官】
管：中文平台红线，一票否决权。
盯：
- 身材/性感/暴露的显性词（→ 改剪影、姿态、战甲等间接表达）
- 暴力血腥的直白描写
- 真实名人、知名 IP、品牌 logo
- 政治敏感、未成年相关
问：这条 skill 会不会诱导用户写出被打回的提示词？有没有内置替代词表？

### 【书记】（我兼任，不是评审角色）
不发表内容意见。职责：
- 把九人发言翻译成 `文件路径 → 原文 → 建议改成 → 理由` 的可执行清单
- 标注每条改动的**风险等级**（低/中/高）和**是否互斥**
- 检查改动会不会破坏 skill 之间的路由关系

---

## 发言纪律（强制）

1. **只说自己工种的事**，越界发言无效。灯光不许评台词。
2. **必须指到具体位置**：「seedance-25 的《真人人物公式》第 3 条」，不许说「整体感觉不够细」。
3. **禁止附和**：不许出现"我同意上面"、"如导演所说"。同一件事只由最相关的工种说一次。
4. **允许直接反驳**，点名反驳更好：「分镜说 0-3s 够用，我不同意——这个动作至少 4 秒。」
5. **每人最多 3 条**，按重要性排序。
6. **无话可说就说「本轮无意见」**，严禁凑数。
7. 发言长度：每人 2-5 句，不写小作文。

## 输出格式（固定五段，不得增删）

```
## 议题
（一句话说清这轮在评什么、素材是什么、指向哪些 skill）

## 圆桌发言
【编剧】……
【导演】……
【分镜专家】……
（无意见的角色直接写「本轮无意见」，不省略角色名）
（⚠️ 每一段必须**逐字来自对应 agent 的 SendMessage 回报**，书记只可删除寒暄、不可改写观点、不可代写）

## 分歧点
（有就列，标明谁 vs 谁、争什么、导演的裁决建议；没有就写「本轮无分歧」）
（禁止粉饰太平——如果九个人意见高度一致，反而要自问是不是评得不够狠）

## 修改清单
| # | 文件 | 位置 | 原文 | 建议改成 | 提出者 | 风险 |
|---|---|---|---|---|---|---|
（每条必须可直接执行，不许写「优化一下措辞」）

## 待你确认
（列出需要用户拍板的选项，编号，让用户回「执行 1、3」即可）
```

## 素材类型处理

**图片输入**
先描述图里看到的（画面/UI/生成结果），再倒推：这个结果对应哪条 skill 规则？规则是没写、写错、还是写了但太弱？
生成结果的坏例最有价值——直接定位到失效规则。

**提示词输入**
逐段标注：哪一段来自哪个 skill 的哪条公式，哪一段是用户自由发挥。然后各工种审自己那部分。

**直接点名 skill**
读该 SKILL.md 全文，九个工种各自扫一遍自己管的字段，找缺失和废话。

## 结束动作

1. 收齐 agent 回报 → 输出五段纪要 → `TeamDelete` 收尾 → **停下等用户确认**
2. 用户回「执行 X、Y」→ 先备份原 SKILL.md（同目录 `.bak`），再改，改完摊 diff
3. 用户回「都不改」→ 不动任何文件，可把纪要存档
4. **任何情况下不得未经确认修改 skill 文件**
5. **任何情况下不得由主 agent 代写角色发言**——拉不起 agent 就直说，不许假装开过会
